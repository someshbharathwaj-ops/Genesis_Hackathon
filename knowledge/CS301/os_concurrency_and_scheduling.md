# Operating Systems (CS301) — Core Concepts Reference

## 1. Process Lifecycle and Process Control Block (PCB)
An Operating System process moves through five distinct states:
- **NEW**: The process is being created.
- **READY**: The process is loaded in main memory and waiting to be assigned to a CPU core by the scheduler.
- **RUNNING**: Instructions are being executed by the CPU.
- **WAITING / BLOCKED**: The process is waiting for an I/O event, signal, or synchronization lock.
- **TERMINATED**: The process has finished execution and its PCB is being reclaimed.

The **Process Control Block (PCB)** stores:
- Process ID (PID)
- Program Counter (PC)
- CPU registers and execution state
- CPU-scheduling information (priority, quantum)
- Memory-management information (base/limit registers or page tables)
- Accounting and I/O status information (open file descriptors)

## 2. CPU Scheduling Algorithms
The CPU scheduler selects a process from the ready queue to execute:

1. **First-Come, First-Served (FCFS)**:
   - Non-preemptive.
   - Suffer from the **Convoy Effect**: short processes stuck waiting behind long CPU-bound processes, increasing average turnaround time.

2. **Shortest Job First (SJF) / Shortest Remaining Time First (SRTF)**:
   - Non-preemptive (SJF) or preemptive (SRTF).
   - Proven to be **optimal** for minimizing average waiting time.
   - Requires predicting the length of the next CPU burst (often using exponential smoothing).

3. **Round Robin (RR)**:
   - Preemptive scheduling with a fixed time quantum $q$.
   - If quantum is too large, degenerates into FCFS. If too small, context-switch overhead dominates.

4. **Priority Scheduling**:
   - Each process is assigned an integer priority.
   - Risk: **Starvation (indefinite blocking)** of low-priority processes.
   - Solution: **Aging** — gradually increasing the priority of processes that wait in the system for a long time.

## 3. Concurrency, Critical Section, and Synchronization

A **Race Condition** occurs when multiple threads or processes access and manipulate shared data concurrently, and the outcome depends on the particular order of execution.

### The Critical Section Problem
To prevent race conditions, entry into the critical section must satisfy three essential requirements:
1. **Mutual Exclusion**: If process $P_i$ is executing in its critical section, no other process can execute in their critical section simultaneously.
2. **Progress**: If no process is executing in its critical section and some processes wish to enter, only processes not in their remainder section participate in the decision, and this selection cannot be postponed indefinitely.
3. **Bounded Waiting**: There exists a bound on the number of times other processes are allowed to enter their critical sections after a process has made a request to enter and before that request is granted.

### Synchronization Primitives
- **Mutex Lock**: A boolean lock variable accessed via atomic `acquire()` and `release()` calls.
- **Counting & Binary Semaphores**:
  - An integer variable $S$ accessed exclusively through atomic operations:
    - `wait(S)` / `P(S)`: Decrements $S$. If $S < 0$, the calling process is blocked.
    - `signal(S)` / `V(S)`: Increments $S$. If $S \le 0$, unblocks a waiting process.

---

## 4. Classical Synchronization Problems
1. **Producer-Consumer Problem (Bounded Buffer)**:
   - Uses `mutex` for buffer mutual exclusion, `empty` semaphore (initialized to buffer capacity $N$), and `full` semaphore (initialized to $0$).
2. **Readers-Writers Problem**:
   - Ensures multiple readers can read concurrently, but a writer requires exclusive mutual exclusion.
3. **Dining Philosophers Problem**:
   - Demonstrates deadlock and resource allocation contention among competing processes.

---

## 5. Deadlocks and Coffman Conditions
A **Deadlock** is a situation where every process in a set is waiting for an event that can only be caused by another process in the set.

### The 4 Necessary Coffman Conditions:
1. **Mutual Exclusion**: At least one resource is held in a non-shareable mode.
2. **Hold and Wait**: A process holds at least one resource and is waiting to acquire additional resources held by other processes.
3. **No Preemption**: Resources cannot be preempted; they can only be released voluntarily by the holding process.
4. **Circular Wait**: A closed chain of processes exists such that each process holds at least one resource needed by the next process in the chain ($P_0 \rightarrow P_1 \rightarrow \dots \rightarrow P_n \rightarrow P_0$).

---

## 6. Virtual Memory and Paging
- **Logical vs. Physical Address**: Logical addresses are generated by the CPU and translated to physical RAM addresses via the Memory Management Unit (MMU).
- **Paging**: Physical memory is broken into fixed-size **frames**, and logical memory is broken into same-sized **pages**.
- **Page Fault**: Occurs when a process accesses a page marked invalid (not currently in physical RAM), triggering an interrupt to swap the page in from disk.
