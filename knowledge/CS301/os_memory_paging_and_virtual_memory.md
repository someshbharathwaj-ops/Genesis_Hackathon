## 1. Paging & Address Translation

**Paging** is a memory-management scheme that permits the physical address space of a process to be noncontiguous, eliminating external fragmentation.

### 1.1 Logical to Physical Address Mapping
- Logical memory is divided into fixed-size blocks called **pages** (size usually 4 KB to 8 KB).
- Physical memory is divided into fixed-size blocks of the same size called **frames**.
- An address generated by the CPU is divided into two parts:
  - **Page number ($p$):** Used as an index into the process page table.
  - **Page offset ($d$):** Combined with the base frame address to define physical address.
- If logical address space is $2^m$ and page size is $2^n$:
  - Higher $m - n$ bits designate page number $p$.
  - Lower $n$ bits designate page offset $d$.

### 1.2 Page Table Structure
The page table maps each page number $p$ to a physical frame number $f$. The physical address is computed as $f \times \text{PageSize} + d$.
- **Fragmentation:** Paging eliminates external fragmentation, but suffers from **internal fragmentation** (the last page allocated to a process is, on average, half full).

## 2. Translation Lookaside Buffer (TLB) & Effective Access Time

Because accessing the page table in main memory doubles memory latency (one access for page table lookup, one access for the actual operand), hardware uses a high-speed cache called the **TLB**.

### 2.1 Effective Access Time (EAT) Calculation
Let:
- $\alpha = \text{TLB Hit Ratio}$
- $\epsilon = \text{TLB Search Time}$
- $t = \text{Main Memory Access Time}$

$$\text{EAT} = (\epsilon + t) \cdot \alpha + (\epsilon + 2t) \cdot (1 - \alpha)$$
- On hit: TLB search + 1 memory access.
- On miss: TLB search + 1 memory access for page table + 1 memory access for data.

## 3. Page Faults & Page Replacement Algorithms

When a process references a page marked with an invalid bit (not in physical RAM), the MMU traps to the OS, triggering a **page fault**.

### 3.1 First-In, First-Out (FIFO)
- Replaces the oldest page in memory.
- **Belady’s Anomaly:** For some page-replacement algorithms (like FIFO), the page-fault rate may *increase* as the number of allocated page frames increases.

### 3.2 Optimal Page Replacement (OPT / MIN)
- Replaces the page that will not be used for the longest period of time in the future.
- Theoretical benchmark; impossible to implement in real time without future knowledge.

### 3.3 Least Recently Used (LRU)
- Replaces the page that has not been used for the longest period of time.
- Belongs to the class of **stack algorithms** and provably **never suffers from Belady’s anomaly**.

## 4. Common Misconceptions & Traps

| Misconception | Correction |
| :--- | :--- |
| **"Paging causes external fragmentation."** | False. Frames and pages are identical fixed sizes, completely **eliminating external fragmentation**. Only internal fragmentation on the final page exists. |
| **"Adding more RAM frames always reduces page faults under all algorithms."** | False. Due to **Belady's Anomaly**, FIFO page replacement can exhibit *more* page faults with 4 frames than with 3 frames for certain reference strings. |
| **"TLB miss causes a page fault."** | False. A TLB miss simply means the translation was not in cache; the page table in RAM may still show the page is present in physical memory. |
